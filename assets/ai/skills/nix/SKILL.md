# Nix

Read [nix-flake-maintenance.md](nix-flake-maintenance.md) first for every Nix
task. It defines the shared inspection, safety, implementation, and validation
workflow.

Then load only the workflow that matches the request:

| Request                                                       | Workflow                                                           |
| ------------------------------------------------------------- | ------------------------------------------------------------------ |
| Diagnose a failure or unexpected evaluation result            | [nix-debugger.md](nix-debugger.md)                                 |
| Design or migrate repository and flake architecture           | [nix-flake-architect.md](nix-flake-architect.md)                   |
| Create or extend a NixOS or Home Manager module               | [nix-module-author.md](nix-module-author.md)                       |
| Author or review shell behavior generated by Nix              | [nix-generated-shell.md](nix-generated-shell.md)                   |
| Contribute to or adopt a nixpkgs package                      | [nixpkgs-package-contribution.md](nixpkgs-package-contribution.md) |
| Review an actual pull request, its checks, or review feedback | [nix-pull-request.md](nix-pull-request.md)                         |
| Restructure existing Nix code while preserving behavior       | [nix-refactor.md](nix-refactor.md)                                 |
| Review local code or a proposed change                        | [nix-reviewer.md](nix-reviewer.md)                                 |

Combine workflows only when the request genuinely spans them. For example, use
the debugger to establish a root cause before using the module author workflow
to implement an explicitly requested fix.

User instructions and repository-local guidance take precedence. Treat this
skill as the reusable Nix baseline, not as a replacement for project-specific
architecture, commands, or policy.
